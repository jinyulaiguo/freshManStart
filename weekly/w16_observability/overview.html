Week 16 · Observability

Agent 可观测性底座：从黑盒到生产级遥测

以 Day 112「AI 研究助手本地化可观测性底座」为北极星：OpenInference Trace + Token/TTFT 计费 + 结构化异常 + Prometheus/Grafana

本周唯一终局：为既有 AI 研究助手接入私有化遥测栈（Phoenix + Prometheus），使每一次 LangGraph 运行都能在本地还原嵌套 Span、美分成本与错误堆栈，并向 Grafana 暴露 QPS / Error Rate / Latency。 Day 106–111 全部是终局交付件的可复用零件，而不是彼此无关的演示脚本。

本周材料约定

日常（Day 106–111）：只维护 notes.md 讲义 + 当日可执行实现代码 / 测试；不写每日 README；禁止 practice.py——入口写在真实模块的 if __name__ == "__main__"。
真实场景硬约束：必须真实调用 LLM（根 .env 的 MiniMax）；Trace/Metrics 必须推到真实组件（Phoenix / Prometheus），禁止 asyncio.sleep 假流水线冒充过关。
终局（Day 112）：才提供项目级 README.md（启动、验收、截图清单）。
基建：infra/docker-compose.yml（Phoenix :6006 · Prometheus :9090 · Grafana :3000）；地址用 0.0.0.0 / 127.0.0.1，勿用 localhost。
环境契约：仓库根 .env.example → 本地 .env。

Agent 线上痛点与可观测性对策

只有日志时的灾难

  • 决策黑盒：无法看到 Thought → Action → Observation 树，死循环只能猜。
  • 瓶颈不可见：端到端 5s，不知道 4.2s 耗在 RAG 还是 LLM。
  • 费用失控：子节点 Token 无法上卷，无法秒级扣费与预算熔断。
  • 故障不可定位：只有 "Error" 字符串，没有 Span 级 traceback。
  • SRE 失明：无 QPS / Error Rate / Latency 分布，洪峰与超时无法告警。
  • 数据出网风险：仅依赖 SaaS 追踪时，内网与合规场景不可用。

Day 112 底座解法

  • Traces (OTel + OpenInference)：Node / RAG / Tool / LLM 嵌套 Span，属性含消息与工具名。
  • Phoenix 本地化：OTLP 进私有容器，UI 还原输入输出。
  • Latency + Token + TTFT：monotonic 计时与美分成本写入根 Trace Attribute。
  • Exceptions：record_exception + 结构化 JSON 日志落盘。
  • Metrics：Prometheus Counter / Gauge / Histogram → Grafana。
  • LangSmith 对照：Day 106 建立直觉；生产主路径以 Phoenix 为准。
